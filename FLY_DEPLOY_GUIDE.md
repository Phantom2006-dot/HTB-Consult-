# Deploying HTB Consult Academy Backend to Fly.io

This guide walks you through deploying the Express backend to Fly.io,
with the frontend served as static files, connected to NeonDB.

---

## Prerequisites

- A [Fly.io account](https://fly.io) (free tier is fine)
- A [NeonDB account](https://neon.tech) with a database created
- Node.js 20+ installed locally
- Git

---

## Step 1 — Install the Fly CLI

```bash
# macOS / Linux
curl -L https://fly.io/install.sh | sh

# Windows (PowerShell)
powershell -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

Then log in:

```bash
fly auth login
```

---

## Step 2 — Get your NeonDB connection string

1. Go to [console.neon.tech](https://console.neon.tech)
2. Select your project → **Connection Details**
3. Copy the **connection string** — it looks like:
   ```
   postgresql://user:password@ep-xxxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
4. Run the database schema on NeonDB using the SQL file in this project:
   - Open the Neon SQL Editor
   - Paste the contents of `htb_database_export.sql` and run it
   - This creates all tables, indexes, and seed data (including the admin user)

---

## Step 3 — Prepare the project for deployment

The deployment builds both the React frontend and the Express backend,
then serves everything from a single Node.js process.

Run the build locally first to confirm it works:

```bash
npm run build
```

This produces:
- `dist/public/` — the compiled React frontend
- `dist/server/` — the compiled Express backend

---

## Step 4 — Files to deploy

The files Fly.io needs are:

```
/                          ← project root (deploy from here)
├── dist/                  ← built output (generated by npm run build)
│   ├── public/            ← React frontend
│   └── server/            ← Express backend
├── package.json
├── package-lock.json
└── fly.toml               ← Fly.io config (create this — see Step 5)
```

**Do NOT deploy the `supabase/` or `backend/` directories** — they are legacy.

---

## Step 5 — Create fly.toml in the project root

Create a file called `fly.toml` in the **root** of the project (not in `backend/`):

```toml
app = "htb-consult-academy"       # Change this to your chosen app name
primary_region = "lhr"            # London — change if you prefer another region

[build]

[env]
  NODE_ENV = "production"
  SERVER_PORT = "3001"

[http_service]
  internal_port = 3001
  force_https = true
  auto_stop_machines = true
  auto_start_machines = true
  min_machines_running = 0

  [[http_service.checks]]
    grace_period = "10s"
    interval = "30s"
    method = "GET"
    path = "/api/health"
    timeout = "5s"
```

---

## Step 6 — Create the Fly.io app

```bash
fly apps create htb-consult-academy
```

> Replace `htb-consult-academy` with the same name used in your `fly.toml`.

---

## Step 7 — Set all secrets on Fly.io

Run **each** of these commands, replacing the placeholder values with your real ones:

```bash
# NeonDB connection string (from Step 2)
fly secrets set DATABASE_URL="postgresql://user:password@ep-xxxx.neon.tech/neondb?sslmode=require"

# JWT secret — use any long random string (keep it the same as your dev secret)
fly secrets set JWT_SECRET="htb-consults-jwt-secret-2025-replit"

# OpenAI — for the AI chat assistant
fly secrets set OPENAI_API_KEY="sk-..."

# Cloudinary — for image uploads
fly secrets set CLOUDINARY_API_KEY="your-cloudinary-api-key"
fly secrets set CLOUDINARY_API_SECRET="your-cloudinary-api-secret"

# SMTP — for password reset emails
fly secrets set SMTP_HOST="smtp.gmail.com"
fly secrets set SMTP_PORT="587"
fly secrets set SMTP_USER="your-email@gmail.com"
fly secrets set SMTP_PASS="your-app-password"
fly secrets set SMTP_FROM="noreply@htbconsults.com"

# Your deployed frontend URL (used in password reset emails)
fly secrets set FRONTEND_URL="https://academy.htbconsults.com"
```

Verify secrets were set:
```bash
fly secrets list
```

---

## Step 8 — Update package.json start script

Make sure the `start` script in `package.json` is correct (it should be):

```json
"start": "SERVER_PORT=3001 node dist/server/index.js"
```

This is what Fly.io runs after the build step.

---

## Step 9 — Deploy

```bash
fly deploy
```

Fly.io will:
1. Build the Docker image
2. Run `npm run build`
3. Start the server with `npm start`
4. Run health checks at `/api/health`

Watch the deploy logs:
```bash
fly logs
```

---

## Step 10 — Verify it's working

```bash
# Check the app status
fly status

# Open it in the browser
fly open

# Test the health endpoint
curl https://htb-consult-academy.fly.dev/api/health
```

## Useful Fly.io commands

| Command | What it does |
|---|---|
| `fly status` | Show running machines |
| `fly logs` | Stream live logs |
| `fly secrets list` | List all secrets (values hidden) |
| `fly secrets set KEY="value"` | Add/update a secret |
| `fly ssh console` | SSH into the running machine |
| `fly apps destroy htb-consult-academy` | Delete the app |
